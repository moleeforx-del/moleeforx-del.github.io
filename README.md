# alethia-next

The alethia.earth site as a Next.js 16 App Router project, rendering identically
to the original Framer static export in `..`.

Live: **https://moleeforx-del.github.io/**

Deployed by `.github/workflows/deploy.yml` on every push to `main`. It must be a
`<user>.github.io` repo, not a project repo: the Framer bundles request the hero
sequence from `/r2proxy/...` at the **domain root**, so a `/<repo>/` subpath
404s the whole sequence. `BASE_PATH` exists for hosts that do serve from a
subpath, but the hero will not work there without editing the bundles.

```bash
npm install
npm run dev     # http://localhost:3100
npm run build && npm start
```

## What is Next.js code and what is not

The site was published from Framer. The visible markup is Framer-SSR'd HTML that
is hydrated in the browser by Framer's own compiled React runtime
(`public/js/react.*.mjs`, `motion.*.mjs`, `framer.*.mjs`, plus 71 more bundles).
Every animation — the preloader, the scroll-scrubbed hero sequence, Lenis smooth
scroll — lives inside those minified bundles.

So the split is:

| Concern | How it is expressed |
| --- | --- |
| Routing | Real App Router routes, one directory per page |
| Page metadata | `export const metadata` / `export const viewport` per route |
| Stylesheet delivery | React `<style precedence>`, hoisted into `<head>` in cascade order |
| Asset serving | `public/`, byte-identical to the export |
| Scroll-sequence proxy | `app/r2proxy/[...path]/route.ts` |
| Legacy `.html` URLs | `next.config.mjs` rewrites |
| Page content and behaviour | Framer subtree, passed through verbatim |

Rewriting the Framer subtree into hand-authored React components would mean
reverse-engineering those bundles and would not render identically. It is
deliberately left untouched.

## Regenerating

`app/**/page.tsx` and `app/**/framer.json` are generated. Edit the generator,
not the output:

```bash
npm run generate
```

`scripts/generate-routes.mjs` reads the 15 `.html` files from the export in `..`,
lifts the head metadata into Next.js constructs, and writes the Framer `#main`
subtree to `framer.json` beside each route.

## Constraints worth knowing

- **Asset URLs inside `#main` stay relative.** The Framer bundles re-render those
  nodes during hydration using the same relative strings; rewriting them to
  root-absolute makes every such node mismatch and tears down the hydrated tree.
  They resolve correctly because each clean route sits at the same directory
  depth as the `.html` file it replaces (`/our-tech/amrv` ≡ `/our-tech/amrv.html`).
- **`#main` must stay a direct child of `<body>`.** The generated cascade includes
  `html,body,#main{...}` and a height chain that a wrapper element would break.
- **`initialScale` is explicitly nulled** in each `viewport` export. Next defaults
  it to `1`; the export ships `width=device-width` alone, and adding
  `initial-scale=1` changes zoom and rotation behaviour on mobile.
- **`og:image` / `twitter:image` are raw `<meta>` tags**, not metadata-API fields,
  because the API resolves them against `metadataBase` and would bake the dev
  origin into the tag.

## The hero scroll sequence

The home page hero is a scroll-scrubbed image sequence. Two things about it are
easy to get wrong:

- **The frames are zero-indexed.** `00000`–`00210` for desktop (211 frames) and
  `00000`–`00209` for mobile (210). Missing frame `00000` does not just drop a
  frame: the loader requests it, 404s, and never completes the intro, so
  `lockScrollDuringIntro` is never released. The symptom is a page stuck on the
  preloader with `<html class="... lenis-stopped">` and a document height equal
  to the viewport — the whole page becomes unscrollable, not just the hero.
  `npm run vendor-frames` verifies the full range; keep it that way.
- **The intro is driven by requestAnimationFrame.** In a headless or
  non-compositing browser (an automated preview pane, a background tab) rAF is
  throttled and the intro never advances, which looks exactly like the bug
  above. Check `document.documentElement.className` before concluding anything:
  if it still says `lenis-stopped` but there are no failed requests, it is
  throttling, not a defect.

## The R2 proxy

A Framer code component on the home page loads its frames from
`/r2proxy/framer/1920/...` and `/r2proxy/framer/mob/...`, which must be
same-origin. The route handler proxies `https://r2-assets.alethia.earth` and
caches responses under `.r2cache/`. The hero sequence is several hundred frames,
so an empty cache makes the first load of `/` take roughly 40 seconds; it is
fast on every load after that.

`AGENTS.md` and `CLAUDE.md` are generated by `next dev`, not hand-written.
